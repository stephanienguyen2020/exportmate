# ExportMate backend

FastAPI + Postgres. Requirements and decisions: [REQUIREMENTS.md](REQUIREMENTS.md).

## Run locally

```sh
cp .env.example .env
docker compose up -d                 # Postgres on 127.0.0.1:5433 (+ exportmate_test DB)
uv sync
uv run alembic upgrade head
uv run python -m app.seed_demo_data --email lan@example.com   # demo company, 12 orders, 3 rules, map data
uv run uvicorn app.main:app --reload --port 8000
```

All settings come from `backend/.env` (app, Alembic, seed and tests), whichever folder you run from. Variables set in the shell override it.

Uploaded documents always go to the Cloud Storage bucket `REGULATION_DOCUMENT_BUCKET`, also when running locally: run `gcloud auth application-default login` once. Without it, uploads and downloads return `503 storage_not_configured`. Tests use an in-memory fake.

API docs: http://127.0.0.1:8000/api/v1/docs

With `AUTH_MODE=dev`, any `Bearer dev:<email>` token signs you in as a verified user:

```sh
curl -H "Authorization: Bearer dev:lan@example.com" http://127.0.0.1:8000/api/v1/overview
```

`dev-unverified:<email>` simulates an unverified email. Production (`ENV=production`) refuses to start unless `AUTH_MODE=firebase`.

Trade map data lives in Postgres. Shared reference data (markets, countries, ports, document kinds,
per-market checklists, sample satellite observations) comes from `app/seed_data/*.json`:

```sh
uv run python -m app.seed_reference_data   # also run by seed_demo_data and by deploy.sh
uv run python -m app.cleanup_imports --older-than-days 30   # delete uploads never committed (run daily)
```

The demo seed adds the demo company's suppliers, their documents and its sites
(`app/seed_data/demo_company.json`, which also holds its About company profile). Observations are samples.

Each market requirement (one item of a market's checklist) cites an official text listed in `app/seed_data/regulation_sources.json` (EUDR, Lacey Act, ISPM 15, …). The reference seed downloads each text once (about 30 MB the first time) and stores it as a shared regulation in the bucket, so it needs internet and `REGULATION_DOCUMENT_BUCKET` (see above). A text that can't be downloaded is skipped with its market requirements, and added on the next run. Tests use a fake download.

## Logging

Every log line carries the request ID (also returned as `X-Request-ID`). Each request logs one
`request.completed` line with method, path, status, duration and the caller's user and company
IDs; services log what they changed (`import.committed`, `trade_map.built`, ...). Production
(`ENV=production`) writes JSON that Cloud Logging parses, grouped by Cloud Trace. Set
`LOG_LEVEL` / `LOG_FORMAT` to change it. Tokens, passwords, file contents and email addresses
are never logged.

## Test and lint

```sh
uv run pytest                                  # needs Postgres; uses TEST_DATABASE_URL
uv run pytest tests/test_imports.py -k commit  # one file / matching tests
uv run ruff check . && uv run ruff format .
```

Tests drop and re-create the test database schema with Alembic, then empty every table after each test.

## Migrations

```sh
uv run alembic revision --autogenerate -m "add exposures"   # after changing app/database/models
uv run alembic upgrade head
```

Check autogenerated files: Postgres enum types need an explicit `DROP TYPE` in `downgrade()`.

## Deploy

Cloud Run + Cloud SQL, created with Terraform. See [../infra/terraform/README.md](../infra/terraform/README.md).

```sh
PROJECT_ID=<project> backend/deploy.sh   # build image, run migrations, roll out
```

## Layout

| Folder | Holds | Rule |
| --- | --- | --- |
| `app/api/` | Routers | HTTP in/out only. No SQLAlchemy. |
| `app/services/` | Business logic | Owns the transaction (`db.commit()`). |
| `app/database/models/` | Tables | One file per area. |
| `app/database/queries/` | Accessors | The only place that builds SQL. Never commits. |
| `app/schemas/` | Request/response models | snake_case in Python, camelCase in JSON. |
| `app/core/` | Config, auth, errors, request ID | |

Every company-scoped route takes a `ViewerContext` / `EditorContext` / `OwnerContext`. The company always comes from the caller's membership, never from the request. Another company's records return `404`.

Responses: `{"data": ..., "meta": {...}}`. Errors: `{"error": {"code", "message", "fieldErrors", "requestId"}}`.

| Area | Endpoints |
| --- | --- |
| Company knowledge | `GET /company/knowledge`: the About company profile and sites, read by the AI service with the user's token |
| Trade map | `GET /trade-map` (markets, placed orders with document checks, suppliers, sites, observations), `GET /trade-map/compare?orderId=&market=` |
